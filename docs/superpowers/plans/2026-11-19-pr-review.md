# PR review implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Open any open GitHub PR in aq's review card; on the user's own PR, comments go to a Claude session that fixes and pushes; on someone else's PR, `?` asks Claude and the comments go to GitHub as one review.

**Architecture:** A new `src/pr/` module holds the GitHub side: listing and reading PRs, preparing the checkout, and placing comments on GitHub's diff. The app keeps an `App::pr_reviews` map from checkout path to `PrReview`; the existing review card, review computation and send path consult it. All `gh`/`git` calls go through the `Runner` trait from `src/flag/facts.rs`, extended for long calls and stdin.

**Tech Stack:** Rust 2024, ratatui, serde_json, `gh` and `git` command lines.

**Spec:** `docs/superpowers/specs/2026-11-19-pr-review-design.md`

## Global constraints

- No new crate dependencies. No network calls in tests: every `gh`/`git` call goes through `Runner`, faked in tests.
- Timeouts: 120 s for `git fetch`, `git worktree add` and `gh pr checkout`; 60 s for `gh pr diff`, `gh pr list` and posting; 10 s for everything else.
- PR worktrees live at `<state dir>/pr/<owner>-<repo>-<number>`, where `<state dir>` is `crate::config::paths().state_dir`.
- "Mine" means the PR author's login equals the user's GitHub login (`flag::facts::load_me`). A teammate's PR is not mine.
- Someone else's PR is checked out with `--detach`; it is never pushed from.
- Comment placement: a line comment only for a line inside GitHub's diff hunks; anything else is a file comment (`subject_type: "file"`) whose body starts `Line {n}: ` or `Lines {a}-{b}: `.
- Keys: `R` (global, outside typing) opens the PR list; on a PR card `i` shows the description, `D` closes the PR review; on someone else's PR `s` comments, `a` approves, `X` requests changes, each through a one-line summary box.
- Existing review cards for sessions behave exactly as before; no existing snapshot changes.
- The working tree is shared with other sessions: never run git stash, checkout, reset or clean in the repo; commit only when the user asks.
- Copy: plain British English, no em dashes.

## Review focus

1. A PR whose head branch is already checked out in a known folder (the user's own PR, usually) is reviewed in that folder; no worktree, no `gh pr checkout` there. Pinned in Task 3.
2. A local branch with the PR head's name that has extra commits: `gh pr checkout` fails, aq shows `gh`'s reason and makes nothing. Pinned in Task 3.
3. A comment on a context line that aq shows but GitHub's diff does not is posted as a file comment, and the card marked it when it was written. Pinned in Tasks 4 and 8.
4. The PR's head moved on GitHub since the checkout: posting is refused with a message to refresh (`r`). Pinned in Task 8.
5. Posting fails (network, permission): the card and its comments stay, with GitHub's message in the status line. Pinned in Task 8.

pub struct RunOpts<'a> { pub timeout: Duration, pub stdin: Option<&'a str> }

### Task 3: Preparing the checkout

**Files:**
- Create: `src/pr/checkout.rs`

**Interfaces:**
- Consumes: Task 1 and Task 2 types.
- Produces:

```rust
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct PrCheckout { pub dir: PathBuf, pub made: bool /* aq made this worktree */,
                        pub base_ref: String /* "origin/<baseRefName>" */ }
pub fn worktree_dir(state_dir: &Path, repo: &str, number: u64) -> PathBuf; // <state>/pr/<owner>-<repo>-<n>
pub fn main_clone(r: &dyn Runner, any_checkout: &Path) -> Result<PathBuf>; // parent of git rev-parse --path-format=absolute --git-common-dir
pub fn prepare(r: &dyn Runner, info: &PrInfo, main: &Path, known: &[(PathBuf, Option<String>)],
               state_dir: &Path) -> Result<PrCheckout>;
pub fn remove(r: &dyn Runner, main: &Path, dir: &Path) -> Result<()>;
```

  `known` is every known checkout of this repo with its current branch. `prepare`:
  1. If `info.mine` and a `known` checkout is on `info.head_ref`: use it, `made: false`, no checkout command run there.
  2. Else the worktree dir: if it exists, reuse it; else `git worktree add --detach <dir>` from `main` (LONG_TIMEOUT).
  3. In it, `gh pr checkout <n> -R <repo>` with `--detach` unless `info.mine` (LONG_TIMEOUT). On failure, remove a worktree made in step 2 and return the error with `gh`'s message.
  4. `git fetch origin <base_ref name>` in the checkout (LONG_TIMEOUT); `base_ref` is `origin/<baseRefName>`.
  `remove` refuses with an error when `git status --porcelain` in `dir` prints anything; else `git worktree remove <dir>` from `main`.

### Task 4: Placing comments on GitHub's diff

**Files:**
- Create: `src/pr/place.rs`

**Interfaces:**
- Consumes: `review::Comment`, `review::Side` (existing; read `src/review.rs` for their fields).
- Produces:

```rust
#[derive(Debug, Clone, Default, PartialEq, Eq)]
pub struct GhDiff { /* per path: new-side lines and old-side lines inside GitHub's hunks */ }
pub fn parse_gh_diff(text: &str) -> GhDiff;
pub fn fits(diff: &GhDiff, c: &Comment) -> bool;   // the whole range is inside one side's hunk lines
pub enum Event { Comment, Approve, RequestChanges }
pub fn review_body(diff: &GhDiff, comments: &[Comment], event: Event, summary: &str,
                   commit: &str) -> serde_json::Value;
```

  `review_body` builds `{"commit_id", "event": "COMMENT"|"APPROVE"|"REQUEST_CHANGES", "body": summary, "comments": [...]}`. A fitting comment is `{"path", "line": end_line, "side": "RIGHT"|"LEFT", "body"}` plus `"start_line": line, "start_side"` when `line != end_line`. A comment that does not fit is `{"path", "subject_type": "file", "body": "Line {n}: {body}"}` (or `"Lines {a}-{b}: "`). Only this round's comments are included. Paths are relative to the repo root, `/`-separated.

**Interfaces:**
- Consumes: Tasks 1-5.
- Produces:

```rust
// src/pr/app.rs
pub struct PrReview { pub info: PrInfo, pub made: bool, pub base_ref: String,
                      pub gh_diff: Option<GhDiff> }
pub struct PrFinder { pub prs: Option<Result<Vec<PrSummary>, String>>, pub filter: TextInput,
                      pub cursor: usize, pub opening: Option<String> /* what is being opened */,
                      pub error: Option<String> }
// src/app.rs
App { …, pub(crate) pr_reviews: BTreeMap<PathBuf, PrReview> }
Overlay::PrFinder(Box<PrFinder>)
Effect::ListPrs { dirs: Vec<PathBuf> }   // one dir per known repo
Effect::OpenPr { dir: PathBuf, repo: Option<String>, number: u64, known: Vec<(PathBuf, Option<String>)> }
Msg::PrList(Result<Vec<PrSummary>, String>)
Msg::PrOpened(Result<(PrInfo, PrCheckout, Option<GhDiff>), String>)
```

  - `R` (global, when no typing overlay is open) opens the finder and emits `ListPrs` for the distinct repos of the known agents' checkouts.
  - In the finder: typing filters by repo, number, title or author; `j`/`k` or arrows move; `Enter` opens the picked PR; when the typed text parses with `parse_pr_ref`, `Enter` opens that PR (repo from the link, else the picked row's repo, else the only repo); `Esc` closes. While opening, the box says `Opening PR #<n>…`; an error stays in the box.
  - The `OpenPr` job runs `load_me`, `view_pr`, `main_clone`, `prepare`, and `gh pr diff <n> -R <repo>` (SLOW_TIMEOUT; a failure gives `None`), on its own thread.
  - `Msg::PrOpened(Ok)`: insert the `PrReview` keyed by the checkout path, close the finder, and emit `Effect::ComputeReview` with `base_ref: Some(..)`, `card: None`, `full_branch: false`, and `agent` = the agent whose checkout is that path, else `AgentId::unknown()`. A PR already open in the queue is shown instead of opening twice.
  - `on_review_computed`: when a PR checkout's diff is empty, set the status `PR #<n> has no changes against <base>` instead of dropping it silently.
  - The turn-end mode check (`app.rs`, the `match self.config.mode_for(checkout)` that decides review/quiz/step on a finished turn) treats a checkout in `pr_reviews` as `Mode::Review`.
  - The list box reuses `ui::workspace::list_box`; each row: `repo #n  title  · author`, with `mine` and `draft` marks.

### Task 7: The PR card and the user's own PR

**Files:**
- Modify: `src/pr/app.rs`, `src/app.rs` (`finish_review`, review key handling), `src/ui/review.rs` (head line, file-comment mark), `src/ask.rs` (`context_for`)

**Interfaces:**
- Consumes: `App::pr_reviews`, `PrReview`, `place::fits`.
- Produces:
  - The review card's head shows `PR #<n> · <title> · by <author>` when its checkout is in `pr_reviews`, plus `(not yours: comments go to GitHub)` when not mine.
  - A comment that does not `fits` GitHub's diff shows a dim `file` tag beside it, from the moment it is written (only when `gh_diff` is `Some`).
  - `i` on a PR card opens the description (`info.body`) in the reader the question card uses (`Overlay::Reader`).
  - `D` on a PR card asks to close the PR review (existing confirm box). On yes: the card goes, `pr_reviews`, `rounds` and the saved draft for that checkout are cleared, and if `made`, `Effect::RemovePrWorktree { main, dir }` runs `checkout::remove`; its error (uncommitted changes, a session in it) is the status line and the worktree stays. A session whose checkout is that dir blocks the removal: status `A session is working in it; the worktree is kept`.
  - `context_for` for a PR card adds the PR's title, number, author and body before the diff, as data.
  - The user's own PR, `s`: the message is `"This is PR #<n> (<url>). Fix what the comments below ask, run the tests, then commit and push to the PR's branch.\n\n"` followed by `review::compose_message`. If a session runs in the card's checkout, it is sent as today. If none does, `Effect::NewSession { dir: checkout, prompt: Some(message), worktree: false }` starts one with it as the first prompt, and the round closes as if sent (saved to `rounds`, card closed, status `Started a session on PR #<n> with your comments`).
  - `a` on the user's own PR approves as today (closes the round).

### Task 8: Posting a review on someone else's PR

**Files:**
- Modify: `src/pr/app.rs`, `src/app.rs` (`Overlay`, `Effect`, `Msg`, review keys), `src/runtime.rs` (job), `src/ui/pr.rs` (the summary box)

**Interfaces:**
- Consumes: `place::review_body`, `Event`, `PrReview.gh_diff`.
- Produces:

```rust
Overlay::PrSubmit { card: u64, event: Event, input: TextInput }
Effect::PostReview { dir: PathBuf, repo: String, number: u64, head_sha: String, body: serde_json::Value, card: u64 }
Msg::ReviewPosted { card: u64, result: Result<usize /* comments posted */, String> }
```

  - On a PR card that is not mine: `s`, `a` and `X` open `PrSubmit` with `Comment`, `Approve` and `RequestChanges`. The box title says which (`Comment on PR #5`, `Approve PR #5`, `Request changes on PR #5`); it shows how many comments will go and how many as file comments; `Enter` posts, `Esc` cancels. `RequestChanges` and `Comment` with no comments and an empty summary are refused in the box (`GitHub needs a comment or a summary`).
  - The `PostReview` job: `gh pr view <n> -R <repo> --json headRefOid` (if it differs from `head_sha`: fail with `PR #<n> changed on GitHub since you opened it: press r to refresh`), then `gh api repos/<repo>/pulls/<n>/reviews --method POST --input -` with the body on stdin (SLOW_TIMEOUT).
  - `Msg::ReviewPosted(Ok(n))`: the card closes; status `Posted your review on PR #<n> with <k> comment(s)`; `pr_reviews` and the worktree are cleared as by `D`. `Err(e)`: the card and comments stay; the status line is `Not posted: <e>`.
  - `r` on a PR card that is not mine also refreshes the checkout (`gh pr checkout <n> --detach`) and `gh_diff` before recomputing; this is the refresh the head-moved message points to.
  - The send-hold guard and `held`/`sending` logic do not apply to these cards (no agent).
